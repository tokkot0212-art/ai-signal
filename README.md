# AIシグナル — X から「根拠のある」AIニュースだけを拾う自分用アプリ

X（旧Twitter）の AI 関連投稿を1日4回自動で集め、**誰が言ったか（専門性）** と **根拠は何か（エビデンス）** で選別し、
iPhone のホーム画面アプリ（PWA）で日本語で読めるようにするツールです。サーバー不要、GitHub だけで動きます。

- アプリ: https://tokkot0212-art.github.io/ai-signal/ （Safari で開いて「ホーム画面に追加」）

```
X API ──(GitHub Actions 1日4回・予算内)──▶ 足切り ──▶ 発言者の判定 ──▶ 話題のまとめ ──▶ 根拠の判定・日本語化（Claude）
                                                                                       │
                                     iPhone アプリ ◀── GitHub Pages ◀── feed.json ＋ 日付ごとの履歴
```

## 1. 何を「シグナル」とするか（選別の基準）

### 根拠（エビデンス）で判定する
| 区分 | 扱い | 例 |
|---|---|---|
| 公式発表 | ✅ シグナル | 企業・研究機関の公式アカウントの発表 |
| 論文・データ | ✅ シグナル | arXiv 論文、公開データ、ベンチマーク結果 |
| **公式評価**（特例） | ✅ シグナル（紹介投稿でも可） | 英・米・日の AISI、NIST、システムカード、METR・Epoch AI・Apollo Research などの評価 |
| 報道 | ✅ シグナル | 記者・メディアの取材記事、一次情報を示した報道 |
| **本人が手を動かした検証** | ✅ シグナル | 自分で作った・動かした・測った結果（手順・数値・成果物あり） |
| 独自データの分析 | ✅ シグナル | 本人が集めた・測ったデータに基づく分析 |
| 意見・感想 | 「意見・噂」タブへ | 根拠を示さない予想・感想（**専門家・有名人でも同じ扱い**） |
| 噂・リーク | 「意見・噂」タブへ | 出典不明・匿名情報 |
| **評論・解説のみ** | ノイズ（除外） | 他人の成果や検証を論評・解説・要約しただけ、まとめ記事、解説動画の紹介 |
| 宣伝 | ノイズ（除外） | セミナー告知、アフィリエイト、情報商材 |

- 判定は Claude が行い、さらに次のルールで補正します
  - 公式評価の機関名・資料名が出てくれば、紹介投稿でも「公式評価」に（`official_eval_keywords`）
  - 「作った」「試した」「I built」など本人の制作報告は、「評論」と誤判定されても「検証」に戻す（`hands_on_keywords`）
  - Claude が判定を**格上げ**できるのは「未確認→有望」の1段だけ（裏付けなしに「確認済み」にはしない）

### 誰が言ったか（専門性）
自己紹介・所属から発言者を **公式／研究者／記者・メディア／実務家／評論・解説／個人／宣伝** に分け、
肩書きや前職（例「Wharton教授」「元Google研究者」）も表示します。公式・研究者・記者は信頼度が上がり、評論・宣伝は下がります。

### 確認済み・有望の違い
- **確認済み**: 公式アカウントの発表、または一次情報＋複数の信頼できる裏付け
- **有望**: 根拠はあるが裏付けがまだ1件

### その他の品質対策
- キーワード探索の投稿は、反応が少ないもの（初期値: 15未満）を取り込む前に捨てる（課金も節約）
- 信頼アカウントの雑談など、AIと関係ない投稿は除外
- 同じ出来事の投稿は Claude がまとめる。ただし**別企業の公式発表どうしは統合しない**／共通の固有名詞がない話題も統合しない
- 青い認証バッジは有料で取れるため加点しない（組織認証のみ少し加点）

## 2. 日本語での表示
各話題に **概要（2〜3文）／理解を深めるポイント／用語メモ** を付けます。英語の投稿には **日本語訳** を併記します。
作った概要・訳・発言者の判定は保存して使い回すため、同じ話題に二重課金しません。

## 3. 費用の管理

### X API（従量課金）
- **1日の予算 = 月の上限 ÷ 請求サイクルの日数**（初期設定 $20 ÷ 約30日 ≒ **$0.67/日**）
- 1日4回（日本時間 7・12・17・22時ごろ）に均等に割り振り、1回あたり約20〜30件を取得
- 取得枠は信頼アカウント約7割・キーワード探索約3割。信頼アカウントのグループは毎回順番に回して偏りなく取得
- 使い残しの繰り越しは1日の1.2倍まで（月末の駆け込み消費はしない）
- 請求サイクルは X の Developer Console に合わせて毎月20日始まり（`cycle_start_day`）
- アプリの最下部に「今日の使用額／今日の予算」と「今サイクルの合計」を表示

### Claude（概要・翻訳・判定）
月数ドル程度の見込み。APIキーは有効期限があるので、切れたら新しいキーを作って GitHub Secrets の `ANTHROPIC_API_KEY` を上書きしてください。

## 4. 履歴（日付ごと・追加費用なし）
- 「シグナル」に入った話題を、**最初に見つけた日（日本時間）ごと**に GitHub に保存
  - `docs/archive/days/YYYY-MM-DD.json` … アプリが読むデータ
  - `docs/archive/days/YYYY-MM-DD.md` … GitHub上でそのまま読める日別まとめ
- アプリの「履歴」タブで日付を選択、‹ › で前後の日へ、検索は全期間が対象、「確認済みのみ」で絞り込み
- 続報があれば同じ日の記録を更新。今の基準で「意見・評論」と判定し直された話題は履歴から外れる（確認済みは残す）
- 保存は GitHub の無料枠内で、API呼び出しも増えないため**費用はかかりません**

## 5. アプリの画面
| タブ | 内容 |
|---|---|
| シグナル | 根拠のある話題（確認済み・有望）。カードに「根拠：〇〇」と発言者の肩書きを表示 |
| 意見・噂 | 根拠を示さない意見・予想、噂・リーク |
| ノイズ | 評論・解説のみ、宣伝、釣り、AIと無関係な投稿（判定理由を確認できる） |
| 履歴 | 日付ごとの記録と全期間検索 |

## 6. 設定の変え方（`config/sources.yml`）
| 項目 | 内容 |
|---|---|
| `trusted.tier1` / `tier2` | 信頼する公式アカウント／研究者・記者（自分の好みに入れ替えるほど精度が上がる） |
| `blocklist` | 除外したいアカウント |
| `budget.monthly_usd` / `cycle_start_day` | X API の月予算と請求サイクル開始日 |
| `budget.run_hours_jst` | 自動実行の時刻（`.github/workflows/curate.yml` の cron と合わせる） |
| `quality.discovery_min_engagement` | キーワード探索の足切りライン |
| `quality.official_eval_keywords` | 特例でシグナルに残す公式評価の機関名・資料名 |
| `quality.hands_on_keywords` | 本人の制作・検証とみなす言い回し |
| `bait_phrases` / `rumor_phrases` | 釣り表現・噂表現 |

## 7. セットアップ（済み）
1. X Developer Console で Bearer Token を取得 → GitHub Secrets `X_BEARER_TOKEN`
2. Claude Console で API キーを取得 → GitHub Secrets `ANTHROPIC_API_KEY`
3. Settings → Pages: `main` / `/docs`、Settings → Actions → Workflow permissions: Read and write
4. 手動で動かすときは Actions →「Curate AI news from X」→ Run workflow

## 8. ローカルで試す
```bash
pip install -r requirements.txt
python scripts/curate.py --fixture tests/fixtures/sample.json   # 架空データで判定
python -m unittest discover tests                              # 判定・予算・履歴のテスト
cd docs && python -m http.server 8000                          # http://localhost:8000
```

## ファイル構成
```
config/sources.yml        信頼アカウント・品質基準・予算などの設定
scripts/curate.py         取得→足切り→発言者判定→話題のまとめ→根拠判定→日本語化→履歴保存
scripts/x_client.py       X API v2 クライアント（標準ライブラリのみ）
docs/                     iPhone用アプリ（GitHub Pagesで配信）
docs/archive/days/        日付ごとの履歴（.json と .md）
.github/workflows/        1日4回の自動実行
data/                     取得済み投稿・著者キャッシュ・判定キャッシュ・予算の記録（自動更新）
tests/                    架空データと判定・予算・履歴のテスト
```

## 注意
- 無料の GitHub では Pages は公開URLになります（`noindex` 付きで検索には出ません）。中身は公開投稿の要約です。
- 判定は AI とルールの組み合わせです。迷う判定は時々出るので、気になるものは基準（設定ファイル）で調整してください。
